# Expo Weather Snack import

This asset-free mirror exists as a workaround for the Expo Snack GitHub importer's current asset-upload failure.
Import the repository URL with folder path `snack` and branch `main`. The Expo SDK targets 57. Both root and mirror runtime dependencies use the same exact SDK-57 pins.

Runtime updates are disabled. Update this mirror together with the root application whenever shared application code changes.

The **Wetter-Karten** tab scrolls vertically, including the radar controls and source links. On short phone screens, swipe up to bring playback/frame controls above the persistent legal footer. The footer occupies its own layout area and remains available. Root and mirror share the fix; it is also applied to the saved SDK-55 Snack without changing its runtime. Browser checks passed at 390×667 and 320×568, including playback, pause and frame switching on the smaller viewport. All 32 UI tests and both web exports pass; physical-device execution remains unverified.

To change Snack's hosted SDK, use the version picker beside Expo in the bottom status bar, align dependencies, and save. The [official website configuration](https://github.com/expo/snack/blob/main/website/src/client/configs/sdk.tsx) also documents `?sdkVersion=…` for deployed preliminary versions hidden from that picker. Testing `https://snack.expo.dev/?sdkVersion=57.0.0` in a separate unsaved Snack on 2026-10-09 produced “The requested Expo version is not yet supported” and a fallback to 54.0.0. The picker still offered only SDK 50–55. The saved weather app remains on 55; the URL parameter cannot supply a missing hosted runtime. New runtime support requires Expo deployments described in its [maintainer upgrade guide](https://github.com/expo/snack/blob/main/docs/expo-sdk-upgrade.md).

The footer and legal-notice modal mirror the root app: educational demonstration, © 2026 Peter Stroessler for his contributions, contact `peter.stroessler@bluewin.ch`, no reuse or sharing of the demo's CARTO key, and legally qualified warranty/liability limitations. The MIT license continues to govern source code, not credentials. Keep `src/legalNotice.json` synchronized with the root and `LEGAL.md`.

The local mirror targets Expo SDK 57.0.27 / React Native 0.86.3 / React 19.2.3, with `sdkVersion: 57.0.0`, following the user's renewed SDK-57 migration request on 2026-10-09. Runtime dependencies are exact-pinned to the root set. The saved hosted Snack was last verified on SDK 55; local changes do not publish it automatically. Do not save SDK-57 dependencies into a hosted SDK-55 runtime. Import this mirror and choose SDK 57 only once Snack actually provides that runtime.

For a phone with SDK-57-compatible Expo Go, run `./run.sh start --go --lan --port 8082` from the repository root and scan its QR code on the same Wi-Fi network. Use an SDK-57 development build if no matching Expo Go client is available. Close and reopen Expo Go after changing SDK versions. The localhost-only web preview on port 8081 cannot be opened from the phone. Physical-device execution requires testing on the phone.

For the documented Android setup, **uninstall the old Expo Go app first**, then open [Expo's SDK-57 Android download page](https://expo.dev/go?sdkVersion=57&platform=android&device=true). For manual installation, download the SDK-57-compatible Android `.apk` from the Assets of an [official Expo Go release](https://github.com/expo/expo-go-releases/releases); the Expo download page may instead direct the current version to Google Play. If Android asks, allow installation for the app used to open the download. Open the newly installed Expo Go and scan the local SDK-57 server QR code. APK installation applies to Android, not iPhone or iPad; see the root README for the steps and [Expo's version-mismatch guide](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/).

CARTO basemaps require your own key. Local Expo runs read `EXPO_PUBLIC_CARTO_API_KEY` from the app's `.env.local` or process environment. The root `.env.local` is not imported into an online Snack. In a runtime without Expo environment loading, supply your own basemap-scoped key through `RadarViewer`'s optional `cartoApiKey` prop in your private Snack configuration; keep it out of this repository. The key is visible in client bundles. Configure appropriate key restrictions in CARTO. Without a key, radar data and attribution remain visible and basemap tiles are not requested.

The hosted SDK-55 `react-native-screens` Babel-loader error was fixed on 2026-10-09 by removing the redundant single-route native stack and its `@react-navigation/native-stack` / `react-native-screens` dependencies. `NavigationContainer` now hosts the three-tab navigator directly. Before this migration, the saved SDK-55 Snack reported no errors after reloading; browser checks verified Berlin search, weather values, five forecast days, tab switching, radar frames/attribution, and the persistent legal footer. SDK-57 root web/iOS/Android exports, the isolated mirror web export, all 32 UI tests, typecheck, lint, dependency checks, clean installation and all 21 Expo Doctor checks passed. Live local browser checks also passed; full results are recorded in the root README and CLAUDE.md. Physical-phone execution still requires device testing. The root Node-only alignment helper stays excluded from the hosted Snack to avoid missing `fs`/`path` dependencies.
